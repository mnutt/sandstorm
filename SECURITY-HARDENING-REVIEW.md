# Security hardening commit review

The 27 commits introduced on `upgrade-cleanup` relative to `meteor-3.4-continuation`, in chronological order. Commit links point to `mnutt/sandstorm` on GitHub and use the final reviewed commit hashes.

## Scoring

- **Impact (1–10):** importance of the problem being addressed, considering severity, reachability, and affected users. 1–3 is narrow defensive robustness, 4–6 is meaningful but limited protection, 7–8 is major availability or security protection, and 9–10 is a serious authentication, authorization, or script-execution boundary.
- **Regression risk (1–10):** estimated likelihood of disrupting legitimate behavior when merged, not the severity of the original bug or a percentage probability. 1–2 is low, 3–4 is moderate, 5–6 is elevated, and 7–10 would indicate high to very high risk. Intended compatibility breaks, such as rejecting previously accepted SMTP certificates, count toward operational regression risk.
- Scores are comparative engineering judgments for the final implementations, including the review fixes and folded tests. They are not CVSS scores or claims that every potential exploit has been demonstrated.

## Validation context

The final code tree passed the 77-test Meteor server suite. Selected native tests and compilation checks were also completed, including the supervisor-cache ownership test and a deliberately broken borrowed-storage variant that failed. A full native integration run and end-to-end browser/identity-provider runs were not completed; the scores reflect those limits, especially for SAML, transport, and grain-lifecycle changes.
